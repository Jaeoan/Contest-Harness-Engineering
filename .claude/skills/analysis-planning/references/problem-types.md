# 문제 유형별 플레이북 (공간 유형은 spatial-risk-analysis 스킬)

## §개체(표형) — "누구부터?"
- 단위: 가구·사람·건물·사업장 등 한 행 = 한 대상. 공공데이터는 개인정보 때문에 **집계 단위(행정동·기관)**로만 오는 경우가 많다 → 단위를 먼저 확인.
- 방법: 베이스라인(현행 선정 기준) → 로지스틱/GBM 분류 → SHAP 요인. 순위가 목적이면 Precision@k, Recall@k.
- 검증: 그룹 분할(같은 대상이 train/test에 동시에 들어가지 않게), 시간 분할.
- 표현: 우선순위 리스트 + 대상별 요인 Top3 카드. 공정성 점검(특정 집단 과소·과대 선정 여부).

## §시계열 — "언제, 얼마나?"
- 단위: 시간 × (지점 또는 전체). 공휴일·날씨·행사 달력을 특징으로.
- 방법: 계절 나이브(작년 같은 주) 베이스라인 → STL/Prophet → GBM(시차 특징). 롤링 원점 검증.
- 지표: MAPE보다 MAE/sMAPE (0이 많으면 MAPE 폭주). 피크 시간 적중률.
- 표현: 추세 차트 + "다음 주 혼잡 예상" 같은 결론 문장, 필요하면 알림.

## §텍스트 — "사람들이 뭐라고 하나?"
- 소스: 민원, 게시판, 후기, 보도자료, 조례. 개인정보 마스킹 먼저.
- 방법: 키워드 빈도(베이스라인) → BERTopic 토픽 → 분류기(소량 라벨) → 근거 검색은 RAG.
- 검증: 무작위 100건 수작업 라벨 대조, 토픽 해석 가능성.
- 표현: 토픽 추이 차트, 대표 원문 인용, 질의응답(RAG).

## §매칭/추천 — "이 사람에게 맞는 것은?"
- 소스: 정책·지원사업 공고(자격 요건 텍스트) + 사용자 입력(나이·지역·소득 구간).
- 방법: 자격 요건을 규칙으로 구조화(LLM 추출 + 사람 검수) → 규칙 필터 → 관련도 순위. 규칙이 먼저, ML은 순위에만.
- 검증: 샘플 페르소나 20명 × 정답 정책 목록으로 Recall.
- 표현: 질문 3~5개 → 맞춤 결과 카드(자격 근거·마감일·신청 링크).

## §네트워크/흐름 — "어떻게 이동·연결되나?"
- 소스: OD 데이터(국가교통DB), 대중교통 승하차, 도로망(OSM).
- 방법: OD 행렬 집계 → 중심성·커뮤니티 탐지 → 접근성(네트워크 거리) → 최적화(MCLP 등).
- 표현: 흐름 지도(이때는 지도가 맞다), 또는 구간 순위 리스트.
