# 공공데이터 기획서 스킬

**요강 양식이 있으면 양식 목차가 아래 흐름보다 우선한다.** 아래 흐름은 양식 칸 안에서 내용을 배치하는 기준으로 쓴다. Word 생성은 `contest-form-document` 스킬.

## 전체 흐름 (안양시 사례에서 검증된 구조)
1. **문제**: 누구나 아는 문제 + 숫자 3개 + 기존 해법의 빈틈 한 문장
2. **왜 이 데이터여야 했나**: 데이터별로 "공공데이터 말고는 구할 데가 없는 이유"
3. **데이터를 겹쳤을 때 생기는 것**: 각각은 목록, 겹치면 지도·순위·예측 (문제에 맞는 것) ("넷 중 하나만 있으면 아무것도 못 한다")
4. **분석**: 방법 → 결과 수치 → 검증(독립 지표) → 해석 한계(상관)
5. **서비스**: 누가, 어떤 결정 순간에, 무엇을 보는가
6. **기대효과/확장성**: 다른 지자체 적용 가능성 (전국 표준데이터 기반이면 강조)

템플릿: `references/proposal-template.md` · 심사기준 매핑: `references/judging-criteria.md`

## 문체 규칙
- 개조식(□ ○ - ※), ~함·~임·~됨. 숫자 먼저, 설명 나중.
- 금지: 경구형 대구, 수사의문문, "결론부터 말씀드리면", 줄표·굵은 글씨 남발, 멋 부린 마무리 문장.
- 주장마다 뉴스·보도자료·통계 링크를 아주 작은 글씨로 단다. 수치는 공식 출처, 뉴스는 문제 존재의 근거로만 쓴다.
- 판단의 근거를 외부로 둔다: 지표를 고른 이유는 표준데이터 항목, 법령, 공식 지침으로 댄다.
- 분석 설명은 대상 하나의 실제 숫자로 단계별로 보여 준다(전체 → 대상 → 데이터별 건수 → 점수 계산).
- 주장 강도는 근거에 맞춘다: 확인 못 한 것은 "없음"이 아니라 "공개 자료에서 확인되지 않음". 외부 검증에 쓴 지표가 전체 점수가 아니라 대리 지표 하나면 그렇게 쓴다.
- 한계를 숨기지 않는다: 인과가 아니라 상관이면 화면과 문서에 참고 정보로 표기한다.

## 데이터 표 규칙
| 데이터셋 | 제공기관 | 건수(전체/대상) | 쓰인 곳(모델 입력 번호) |
- "쓰인 곳"은 모델 특징 번호와 1:1로 대응. 모델에 없는 데이터는 "검토했으나 최종 미반영" 별도 표.
- 링크는 data-scout가 확인한 것만. 미확인은 제출 전 반드시 해소.

## 제출 전 체크
- [ ] 모든 숫자가 `docs/04-analysis-report.md` 또는 코드 출력과 일치 (수치 대조표)
- [ ] 요강의 필수 항목 순서·분량 준수, 본문이 양식 표 밖으로 나가지 않음
- [ ] 요약서와 보고서의 숫자·용어·데이터 종수 일치, 그림 속 화면이 현재 화면과 일치
- [ ] 출처 없는 주장 0건 (수상 이력·타 사업 언급도 포함)
- [ ] "인과/원인" 단어 검색 → 근거 없으면 수정
- [ ] 다른 지역 데이터 혼입 없음 (지역 필터 건수 확인)
