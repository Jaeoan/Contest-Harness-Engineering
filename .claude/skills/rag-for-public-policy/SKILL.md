# 공공 문서 RAG 스킬

## 두 가지 용도
- **(A) 기획 근거 RAG**(내부): 문제 근거·기존 정책·예산 사례를 빠르게 찾는다. 품질보다 속도, 로컬 실행.
- **(B) 서비스 RAG**(외부): 사용자 질문에 조례·안내문 근거로 답한다. 인용·거절·평가 필수.

## 파이프라인 기본값 (바꾸려면 평가 결과로 증명)
| 단계 | 기본값 | 이유 |
|---|---|---|
| 파싱 | PDF: PyMuPDF / 표 많으면 Docling. HWP: 한글 변환(hwp5txt 등) 경로를 먼저 검증 | HWP 비중 높음 |
| 청킹 | 조례·법령: **조(條) 단위** + 상위 장·절 제목을 메타데이터로. 보고서: 헤더 기반 → 600~800자 재분할, 100자 겹침 | 구조 보존 |
| 메타데이터 | source, doc_type, org, region, date, article_no | 지역·기간 필터 필수 |
| 희소 검색 | BM25 + 한국어 형태소 분석(kiwipiepy) | 법률 용어·고유명사 |
| 밀집 검색 | 다국어 임베딩(예: BGE-M3 계열) — 코퍼스 샘플로 2개 이상 비교 | 벤치마크≠우리 코퍼스 |
| 결합 | RRF(k=60), 가중치는 골든셋으로 튜닝 | |
| 저장 | PostgreSQL + pgvector (HNSW) — 백엔드 DB 재사용 | 인프라 1개 |
| 리랭커 | precision 병목일 때만 (다국어 cross-encoder) | 지연 비용 |
| 생성 | 인용 강제: [문서명 제n조 (날짜)]. 근거 없으면 "자료에서 찾지 못했습니다" | 신뢰 |

## 평가 (먼저 만든다)
- 골든셋 30문항 이상: 질문 / 정답 문서 / 정답 문단 / 정답.
- 지표: Recall@5, MRR, RAGAS faithfulness·answer_relevancy·context_precision.
- 목표: Recall@5 ≥ 0.8, Faithfulness ≥ 0.85. 변경은 한 번에 한 변수.

## 참고 프레임워크 (변경 감시 대상)
LlamaIndex/LangChain(조립형), RAGFlow(문서 파싱 통합 플랫폼), LightRAG(그래프 강화 검색), RAGAS(평가). 서비스(B)에는 조립형 + pgvector를 기본으로 한다 — 운영 컴포넌트를 늘리지 않기 위해.

## 개인정보
민원 텍스트는 이름·전화·주소·차량번호 마스킹 후 인덱싱. 원문은 `data/raw`(git 제외)에만.
