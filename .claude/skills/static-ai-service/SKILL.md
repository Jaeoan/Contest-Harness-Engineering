# 정적 웹 + AI 서비스 스킬

## 규모 고르기 (GATE B에서 사용자가 선택)
| 규모 | 언제 | 구성 |
|---|---|---|
| 화면 시안 | 제출물이 문서뿐이고 화면은 그림으로 충분 | 스크린샷·스토리보드 |
| 정적 웹 | 결과가 고정된 분석 파일 | React + `frontend/public/data/*.json` |
| 정적 웹 + 서버 함수 | 실시간 LLM 호출 1~2개가 필요 | 위 + `frontend/api/*.ts` |
| 전체 백엔드 | 로그인·쓰기·갱신되는 DB가 핵심 | Spring Boot + PostgreSQL (CLAUDE.md 0절) |

위 표의 작은 규모부터 검토하고, 부족한 이유가 있을 때만 다음 규모로 올린다. 데이터 내보내기 스크립트와 스키마 문서를 남긴다.

## AI 문장은 미리 만들고 검증한다
1. 대상별 설명은 분석 스크립트에서 오프라인으로 생성해 JSON에 넣는다. 브라우저는 키가 필요 없다.
2. **숫자 검증**: 문장 속 모든 숫자가 그 대상의 허용 숫자 목록에 있는지 코드로 검사한다. 실패하면 `verified=false`로 두고 화면에는 템플릿 문장을 "자동 문장" 라벨로 보여 준다.
3. **숫자가 맞아도 뜻은 틀릴 수 있다.** 단위 오인(횟수를 "N곳"으로 쓰는 등)을 표본으로 사람이 읽어 확인한다. "틀린 숫자 0건"은 이 확인까지 한 뒤에만 쓴다.
4. 원본 응답을 저장하고, API 호출 없이 다시 검사하는 옵션(`--reverify`)을 둔다.
5. 화면에 "AI 요약" 라벨과 검증 상태를 표시한다.

## 실시간 LLM
- 키는 서버 함수의 환경변수에만 둔다. `VITE_` 접두사 변수에 넣지 않는다.
- 호출 로직을 한 파일에 두고 Vite 개발 서버 플러그인과 서버 함수가 함께 쓰게 해서 로컬과 운영의 동작을 맞춘다.
- 정책 답변의 근거는 직접 확인한 원문으로 제한하고 답변에 출처를 표시한다.
- 무료 등급은 분당·일일 토큰 한도를 확인해 배치 크기와 재시도를 정한다.

## AI 분류 평가
- 평가셋의 출처를 그대로 쓴다. 직접 만든 시연 문장이면 "실제 데이터가 아님"을 문서에 명시한다.
- 합격 기준을 먼저 정한다: 정확도 기준과 다수 클래스 베이스라인 초과.

## 배포 (Vercel, 사용자 승인 후)
1. `frontend/vercel.json`: `framework: vite`, `outputDirectory: dist`, `/api/` 외 경로는 `index.html`로 rewrite.
2. 운영 환경변수에 키를 넣는다. **PowerShell 파이프로 넣으면 BOM이 붙어 인증이 실패할 수 있으니** 넣은 뒤 실제 호출로 확인한다.
3. `frontend/`에서 `npx vercel deploy --prod --yes`.
4. 배포 주소를 열어 화면과 AI 호출을 확인한 뒤 문서에 주소를 쓴다.
5. 위성·지도 타일은 운영 이용 조건을 확인한다. 확인 못 하면 문서에 ⚠️로 적는다.
